# MyBricks Web

Front-end of **MyBricks**, a real-estate portfolio management platform: properties, clients, rental contracts and short-stay reservations, finances and portfolio KPIs (yield, cap rate, NOI, IRR).

> Portfolio project. API: [my-bricks-back-end](https://github.com/JoaoAlfredoMader/my-bricks-back-end).

## Stack

- **React 19** + **TypeScript** (strict) on **Vite**
- **TanStack Router** (file-based routes) and **TanStack Query**
- **Tailwind CSS 4** and **shadcn/ui** on **Base UI**
- **Vitest** + **Testing Library**
- **oxlint**

Planned with the app screens: typed API client generated from the back-end OpenAPI document, Better Auth client, React Hook Form + Zod, TanStack Table, charts and maps.

## Getting started

Node 22 or newer.

```bash
npm install
npm run dev        # http://localhost:5173
```

In development Vite proxies `/api` to `http://localhost:3000`, so the browser talks to one origin and the session cookie works as it will in production. Start the API from the back-end repository (`npm run db:up`, `npm run dev`; see its README).

## Project structure

```
src/
├── app/                 # query client and router factories
├── routes/              # TanStack Router file routes (one file per URL)
├── routeTree.gen.ts     # generated by the router plugin on dev/build; committed
├── features/<feature>/  # everything a feature needs: components, hooks, lib, styles
│   └── landing/         # the public home page
├── components/ui/       # shadcn/ui components (generated by its CLI)
├── lib/                 # shared helpers
└── test/                # Vitest setup and render helpers
```

- **Routes stay thin.** A route file declares the URL and renders a component from its feature.
- **Features own their logic.** Data access will live in each feature's query and mutation hooks; components do not call the API directly.
- **Business rules stay in the API.** The front-end formats what the API returns (money in cents, fractions as percentages) and never recalculates derived values.

## Landing page

The home page (`src/features/landing`) is an illustrated scene of a residential building drawn in SVG, with a day and a night version. The visitor's choice is remembered in `localStorage`; the first visit follows the system's color scheme. Motion is limited to the opening of the page and the switch between day and night, and it is turned off when the system asks for reduced motion.

The landing has its own palette and typeface (Bricolage Grotesque), scoped to `.landing`; the app screens will get their own theme.

## Tests

```bash
npm test
```

Tests render the real route tree with a memory history (`src/test/render-route.tsx`). The router plugin is left out of the test config because the generated route tree is committed and the plugin's watcher keeps Vitest workers from starting.
